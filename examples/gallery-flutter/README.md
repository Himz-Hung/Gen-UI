# gallery-flutter — example

Every shipped contract (76) materialized in Flutter, following the conventions `fw docs` prints.

```sh
npm test                  # fw check (81 passed) + fw verify (contract checks) + flutter analyze + flutter test
flutter run -d chrome     # the gallery Home screen
```

| | |
|---|---|
| `lib/ui/*.dart` | one `Ui<Name>` widget per contract, each passing `fw verify`; `icons.dart` maps icon names to Material icons |
| `lib/ui/ui.dart`, `lib/ui/tokens.g.dart` | generated by `fw` on every command |
| `lib/screens/home_screen.dart` | a screen composed from `lib/ui` only, checked by `fw check lib/screens` |
| `lib/main.dart` | hand-written shell (MaterialApp, Scaffold, scrolling) |
| `test/g1_test.dart` … `g7_test.dart` | a widget test per component: renders, emits its events, honours disabled / loading |
| `test/fw/` | generated by `fw verify` from the contracts' `checks` (git-ignored, rebuilt on every run) |

Twelve components were written by hand (the templates Button, Image, Select, Card, and FloatingActionButton, HorizontalScroll, ImageViewer, RichText, DateRangePicker, AvailabilityCalendar, SiteHeader, SiteFooter); the rest were written
by coding agents from `fw docs`, then checked by `fw verify`, `flutter analyze` and the tests.

## Theming

`ui-spec/project.ts` defines a light and a dark color scheme (identical in both galleries). The gallery has a light / system / dark switch in the app bar (`lib/main.dart`: `theme` / `darkTheme` / `themeMode` from `lib/ui/theme.g.dart`); every component reads `context.ui`, and `test/theme/theme_test.dart` checks both modes.
`fw check` verifies the contrast of every text / background pair in both schemes.

## Behavioural checks

`fw verify` runs the `checks` of the 53 contracts that have them (124 checks), including the layout ones React
skips: all pass. Found and fixed by them in 1.3: Button kept neither its width while loading nor its height
(Material padded it to 48), IconButton and FloatingActionButton were padded to 48 too (Material controls now use
`MaterialTapTargetSize.shrinkWrap` so the laid-out size is the contract size), Input / Textarea / Slider labels were
not the field's accessible name (`MergeSemantics` now), Spinner was not a live region, SegmentedControl options were
buttons instead of radios. Still reported as warnings: arrow keys in Tabs and SegmentedControl.

## Contract rules not fully met here

Reported by the implementations, kept visible on purpose:

- **Keyboard:** arrow-key movement inside Tabs, SegmentedControl, Sidebar and Stepper is not implemented (press works).
- **Assistive tech:** SwipeActions and PullToRefresh expose tap/long-press actions instead of custom semantics actions; InfiniteScroll does not announce "N more loaded"; charts have a summary label but no data-table alternative; Avatar is always labelled.
- **Layout owned by the screen:** TopBar stickiness, BottomNav fixed position, and Table's vertically sticky header depend on the screen's scroll container.
- **Approximations:** Breadcrumbs collapse by estimated text width; exact pixel sizes of Checkbox / Switch / Radio / NumberInput buttons follow Material defaults closely, not exactly; BottomNav's active icon is not a filled variant (one icon per name in `icons.dart`); LineChart has no axis tick labels or hover bubble; BarChart is built from widgets rather than CustomPaint; Drawer closes on a fling in any direction; ConfirmDialog's initial focus lands on the button wrapper.
- **New ones:** DateRangePicker uses the platform range picker (booked days are unselectable, a range crossing one is rejected rather than shown as disabled while picking, one month at a time); AvailabilityCalendar has no arrow-key movement; SiteHeader is sticky only when the shell places it above the scroll view; HorizontalScroll snaps only when `itemWidth` is set; RichText handles the documented subset only (nested emphasis inside links is not parsed); ImageViewer's swipe-down-to-close needs a fast fling.
- **No plugins:** Video renders poster, controls and states but does not play (add `video_player`); FileUpload renders and emits, picking files is the screen's job; FormField cannot shrink the labels of its children.
